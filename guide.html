01이 앱은 무엇인가

Harness Studio는 코딩 에이전트(Claude Code, Codex, Cursor 등)를 개인의 터미널 습관에서 조직의 운영 체계로 옮기는 과정을 다루는 학습·설계 도구입니다. 용어 하나로 줄이면 하네스(harness) — 모델이 일하는 환경 전체, 즉 문맥·기억·도구·권한·검증·배포·정책을 설계하는 일입니다.

왜 이런 앱이 필요한가

데모에서는 잘하던 에이전트가 실제 업무에서 흔들리는 이유는 대개 모델이 아니라 환경입니다. 세션이 바뀌면 맥락이 사라지고, 무인 실행에서는 승인해 줄 사람이 없고, 팀마다 설정이 갈라집니다. 이 앱은 그 문제를 진단 → 학습 → 조립 → 산출물 순서로 좁혀 들어갑니다.

누구를 위한 앱인가

대상이 앱에서 하는 일
개발자챕터로 개념을 잡고, CLAUDE.md·훅·CI 워크플로 템플릿을 바로 저장소에 커밋
팀 리드 · CTO성숙도 진단으로 현재 위치를 확인하고, 3계층 하네스 청사진으로 도입 범위 합의
플랫폼 · DevEx관리형 설정·마켓플레이스·감사 정책의 경계를 설계
강사 · 워크숍 진행자발표자 모드로 90분 워크숍을 그대로 진행

세 가지 원칙

  • 대화가 아니라 저장소. 세션이 끊기면 대화는 사라집니다. 남는 것은 파일과 검사뿐입니다.
  • 문서는 확률, 훅은 결정. 반드시 지켜야 하는 규칙은 실행 단계로 옮깁니다.
  • 측정 없는 개선은 추측. 바꾸기 전과 후를 같은 기준으로 비교합니다.
앱이 하지 않는 일

이 앱은 에이전트를 대신 실행하지 않습니다. 코드를 생성하거나 저장소에 직접 커밋하지도 않습니다. 설계와 학습을 담당하고, 실제 실행은 여러분의 Claude Code·CI가 맡습니다. 생성된 파일은 복사하거나 ZIP으로 내려받아 직접 커밋합니다.

025분 안에 시작하기

  1. 앱을 엽니다

    배포된 주소로 접속하거나, 내려받은 폴더에서 python3 -m http.server 8080 후 localhost:8080을 엽니다. 파일을 더블클릭해 file://로 열면 오디오와 오프라인 기능이 동작하지 않습니다.

  2. 진단부터 합니다

    상단 Diagnose에서 10문항을 0–2로 표시합니다. 1분이면 끝나고, 지금 어디를 먼저 손대야 하는지 3개 항목이 나옵니다.

  3. 추천받은 챕터를 읽습니다

    Learn에서 해당 챕터로 이동합니다. 챕터당 6–8분, 상단 오디오 버튼을 누르면 2분 요약으로 대체할 수 있습니다.

  4. 청사진을 만듭니다

    Build에서 4문항에 답하고 선택 항목 ZIP을 내려받습니다. CLAUDE.md와 limits.yaml만 먼저 커밋해도 첫 하네스가 됩니다.

  5. 설치해 둡니다

    모바일은 홈 화면에 추가, 데스크톱은 주소창의 설치 아이콘. 이후에는 오프라인에서도 전체 콘텐츠가 열립니다.

처음 온다면 이 순서만

진단 → Learn 1·3·6장(루프 · 저장소 · 훅) → Build ZIP → 커밋. 나머지는 필요할 때 꺼내 보는 참고서로 쓰시면 됩니다.

04Learn — 15개 챕터

PART 1부터 5까지, 15개 챕터 · 51개 개념 블록 · 45개 체크 항목 · 30문항 퀴즈로 구성됩니다. 챕터 하나는 같은 리듬으로 반복됩니다.

읽는 방법

  • 개념 블록은 왼쪽에 태그(관찰·행동·검증·개입 등), 오른쪽에 설명이 붙습니다. 태그만 훑어도 구조가 잡힙니다.
  • 일상 비유는 개념을 자기 업무로 번역하는 구간입니다. 개발자가 아니어도 여기서 이해가 됩니다.
  • 실무 체크는 체크박스로 저장됩니다. 다 채우지 않아도 되고, 하나를 이번 주 할 일로 고르면 됩니다.
  • 퀴즈는 2문항입니다. 선택하면 정답이 초록, 내가 고른 오답이 주황으로 표시되고 해설이 열립니다. 퀴즈 다시 풀기로 초기화할 수 있습니다.

이동과 기록

동작방법
다음 · 이전 챕터→ ← 또는 본문 하단 다음 → 버튼
완료 표시이 챕터 완료 표시 — 좌측 목록에 점이 찍히고 상단 진행률이 올라갑니다
챕터 검색상단 검색창에 개념어 입력 (예: 훅, 샌드박스)
빠른 이동⌘K / Ctrl K 커맨드 팔레트에서 챕터·화면·동작 검색
진행률 계산 방식

진행률은 완료 표시한 챕터 수 ÷ 15입니다. 체크리스트나 퀴즈 정답은 진행률에 영향을 주지 않고 별도로 저장됩니다.

05Practice — 카드와 시나리오

읽는 것과 꺼내 쓰는 것은 다릅니다. Practice는 개념을 기억하는 트랙과 판단을 훈련하는 트랙으로 나뉩니다. 상단의 두 버튼으로 전환합니다.

Track A플래시카드 33장

전 챕터의 핵심 용어를 모은 덱입니다. 카드를 클릭하거나 Space를 누르면 정의가 열립니다.

  • 알고 있음 — 암기로 분류. 덱에서 뒤로 밀려 다시 나오지 않습니다.
  • 다시 보기 — 학습 필요로 분류. 다음 순회에서 앞쪽에 배치됩니다.
  • 상단 진행 바: 회색(미확인) · 주황(학습 필요) · 초록(암기)

앱을 새로 열면 미암기 카드가 먼저 나오도록 자동 정렬됩니다. 5분이면 전체를 한 번 훑을 수 있습니다.

Track B시나리오 랩 8개

실제 사고 상황을 주고, 세 가지 대응 중 하나를 고르게 합니다. 정답 여부보다 어느 계층에서 막혔는지를 확인하는 것이 목적입니다.

예: 야간 의존성 업데이트가 테스트를 깨뜨렸다 — 에이전트가 실패한 테스트를 수정해 통과시켰다면?

  • 선택하면 즉시 판정과 해설, 그리고 원칙 한 줄이 표시됩니다.
  • 다음 시나리오 → 로 8개를 순서대로 진행합니다. 하단 점 표시로 진행 상황을 봅니다.
  • 처음부터 로 전체 판정을 초기화할 수 있습니다.
워크숍에서 쓰는 법

팀으로 진행할 때는 시나리오를 소리 내어 읽고 30초 토론 후 투표하게 하세요. 정답을 맞히는 것보다 "우리 팀은 어느 계층이 비어 있었나"를 말하게 하는 편이 효과가 큽니다.

06Build — 하네스 조립

네 가지 질문에 답하면 조직 공통 · 프로젝트 · 개인 3계층 하네스가 조립되고, 곧바로 커밋할 수 있는 파일 10종이 생성됩니다.

질문 4개

질문결과에 미치는 영향
Q1 규모목표 수준(L1 개인 / L2 팀 / L3 조직)과 조직 계층의 두께. 100명 이상이면 조직 계층이 활성화됩니다.
Q2 자동화테스트 게이트, 훅, CI 워크플로, 중단 조건의 포함 여부.
Q3 보안 민감도샌드박스 정책, 감사 로그, 거부 목록의 강도. ‘높음’이면 감사 로그가 추가됩니다.
Q4 기존 자산이미 있는 것에 따라 스킬·서브에이전트 항목을 중복 생성하지 않습니다.

결과 읽는 법

오른쪽 아래에는 파일 트리와 다음 할 일 3개가 함께 나옵니다. 트리는 지금 설정에서 실제로 만들어져야 하는 구조이고, 다음 할 일은 그 구조를 채우는 순서입니다.

시작 파일 10종

목록에서 체크하면 오른쪽에 실제 내용이 미리보기로 나옵니다. 빈 템플릿이 아니라, Q1–Q4 답변이 반영된 파일입니다.

파일용도
CLAUDE.md저장소 규칙 — 스택, 명령, 완료 기준, 금지 사항
.claude/settings.json권한(allow/ask/deny)과 훅 연결. 보안 민감도에 따라 deny 목록이 달라집니다
.claude/skills/release/SKILL.md릴리스 절차 스킬 — 사전 확인부터 배포까지 5단계
.claude/agents/explorer.md탐색 전담 서브에이전트 — 코드 수정 금지, 요약 형식 지정
hooks/pre-commit-guard.sh커밋 전 위험 명령 차단 훅 (force push, 시크릿 읽기, 파괴적 DB)
.github/workflows/agent.yml무인 CI 워크플로 — PR 트리거, 검증 게이트, 타임아웃
harness/limits.yaml예산·변경 범위 상한, 중단 조건, 사람 에스컬레이션 기준
docs/handoff.md세션 인수인계 양식 — 상태, 시도, 실패 이유, 다음 할 일
managed-settings.json조직 관리형 설정 — 프로젝트가 덮어쓸 수 없는 정책
CODEOWNERS민감 경로 소유자 — 인프라·마이그레이션·정책 파일 리뷰 강제

내려받기

  • 복사 — 청사진 마크다운을 클립보드로
  • .md 다운로드 — harness-blueprint.md 단일 파일
  • 선택 항목 ZIP — 체크한 파일 + 청사진을 폴더 구조 그대로 압축 (harness-kit.zip)
  • 이 파일 복사 — 미리보기 중인 파일 하나만 복사
커밋 순서

CLAUDE.md → harness/limits.yaml → hooks/pre-commit-guard.sh 순서가 안전합니다. agent.yml과 managed-settings.json은 팀 합의가 끝난 뒤에 넣으세요. 설정만 먼저 들어가면 아무도 이유를 모르는 채로 유지됩니다.

07Diagnose — 성숙도 진단

10문항을 각각 없음(0) · 부분(1) · 있음(2)으로 표시합니다. 총점 20점 만점으로 다섯 단계 중 하나가 나옵니다.

점수단계의미
0–3L0 대화형 사용개인이 대화로만 쓰는 단계. 규칙이 저장소에 없습니다
4–8L1 개인 하네스규칙 파일과 검사 명령이 한 사람 손에 정리됨
9–13L2 팀 표준스킬·훅·서브에이전트가 저장소에 있고 리뷰와 연결됨
14–17L3 조직 거버넌스관리형 설정·마켓플레이스·감사가 운영됨
18–20L4 무인 운영예산·중단 조건·평가 하네스로 무인 실행을 통제

점수 아래에는 가장 낮은 항목 3개가 다음 할 일로 제시됩니다. 이 앱은 점수를 올리는 것보다 다음 한 걸음을 정하는 데 목적이 있습니다.

팀으로 쓸 때

각자 진단한 뒤 항목별로 평균을 내보세요. 총점 평균보다 편차가 큰 항목이 실제 문제입니다. 어떤 팀은 훅을 쓰고 어떤 팀은 모른다면, 그건 도구 문제가 아니라 배포 문제입니다.

08Reference — 부록

다 읽은 뒤에도 계속 꺼내 보는 페이지입니다. 위에서 아래로 여섯 구역입니다.

구역내용

기록 옮기기

JSON 내보내기는 진도·퀴즈·카드·시나리오·진단·설정을 한 파일로 저장합니다. 다른 기기나 브라우저에서 가져오기로 그대로 복원됩니다. 팀원에게 "내가 만든 진단 결과"를 보여줄 때도 이 파일을 쓰면 됩니다.

인쇄 · PDF는 현재 화면을 인쇄용으로 정리합니다. 좌우 레일과 내비게이션이 빠지고 본문만 남습니다.

09발표자 모드

강의실·워크숍용 전체화면 발표 화면입니다. 챕터 덱과 워크숍 덱 두 가지가 있습니다.

퀴즈 슬라이드 운용

퀴즈 슬라이드는 처음에 정답이 가려진 상태로 열립니다. 청중에게 묻고 토론을 받은 뒤 슬라이드를 클릭하거나 Enter를 누르면 정답과 해설이 나타납니다. 진행 바(하단 가로 막대)를 클릭하면 원하는 슬라이드로 바로 점프합니다.

두 화면으로 발표하려면

노트북을 프로젝터에 연결한 뒤 F로 전체화면을 켜세요. 노트(N)는 화면 오른쪽 아래에 겹쳐 뜨므로, 노트북 화면에서만 보고 싶다면 브라우저 창을 복제하지 말고 확장 모드로 두고 발표 화면을 프로젝터로 보내면 됩니다.

10오디오 요약

챕터마다 1분 22초–2분 16초 분량의 내레이션이 있고, 15편 합계 25분 36초입니다. 출퇴근이나 이동 중에 전체를 한 번 들을 수 있는 길이입니다.

재생하는 세 가지 방법

  • 챕터 상단 카드 — 재생 버튼을 누르면 즉시 시작
  • Reference → 오디오 라이브러리 — 15편 중 원하는 편만
  • 하단 미니 플레이어 — 재생 중 화면을 이동해도 계속 재생됩니다

설치

  1. Android · 데스크톱 (Chrome / Edge)

    주소창 오른쪽의 설치 아이콘, 또는 앱 상단의 앱 설치 버튼을 누릅니다.

  2. iPhone · iPad (Safari)

    공유 버튼 → 홈 화면에 추가. iOS는 자동 설치 배너가 없어 이 경로만 있습니다.

  3. 설치 후

    독립 창으로 열리고, 오프라인에서도 전체 콘텐츠와 오디오가 동작합니다. 앱 아이콘 길게 누르면 카드·빌더·진단 바로가기가 나옵니다.

기기 간 동기화는 없습니다

기록은 기기에 남습니다. 다른 기기로 옮기려면 Reference → JSON 내보내기 후 새 기기에서 가져오기 하세요. 브라우저 데이터를 삭제하면 기록도 사라집니다.

테마

상단의 해 아이콘으로 라이트/다크를 전환합니다. 선택은 저장되어 다음 방문에도 유지됩니다.

12배포하기

정적 사이트라 서버가 필요 없습니다. GitHub Pages를 권장합니다.

  1. 저장소를 만듭니다

    이름은 자유 (예: harness-studio). Public이면 무료로 Pages를 쓸 수 있습니다.

  2. 파일을 올립니다

    ZIP을 풀어 전체를 푸시합니다. index.html, manifest.webmanifest, sw.js, assets/, audio/, .github/workflows/pages.yml이 모두 필요합니다.

  3. Pages를 켭니다

    저장소 Settings → Pages → Source에서 GitHub Actions를 선택합니다. 이후 main에 푸시할 때마다 자동 배포됩니다.

  4. 주소 확인

    https://<아이디>.github.io/harness-studio/ — 첫 배포는 1–2분 걸립니다.

명령설명
python3 build.pysrc/*를 index.html과 harness-studio.html로 인라인 빌드. 서비스 워커 버전도 갱신
python3 -m http.server 8080로컬 확인. 서비스 워커와 오디오는 http(s)에서만 동작
unzip -t harness-kit.zip내려받은 산출물 무결성 확인

HTTPS가 필수입니다. 서비스 워커와 설치 기능은 https 또는 localhost에서만 활성화됩니다. 사내 서버에 올린다면 인증서를 반드시 적용하세요.

단일 파일로 배포하고 싶다면 harness-studio.html 하나만 올려도 앱은 동작합니다. 다만 오디오·오프라인·설치 기능은 폴더 구조가 있어야 하므로 권장하지 않습니다.

13콘텐츠 수정하기

챕터·퀴즈·카드·시나리오는 모두 데이터 파일에 모여 있습니다. 코드를 건드리지 않고 문구를 고칠 수 있습니다.

파일무엇이 들어 있나
src/data.js15개 챕터(개념·비유·체크·퀴즈·카드), 시나리오 8개, 템플릿 10종, 부록, 진단 문항, 오디오 길이
src/app.js화면 렌더링, 플레이어, 발표자 모드, ZIP 생성, 저장 로직
src/styles.css전체 디자인 토큰(색·타이포·간격)
index.template.html화면 골격. 빌드 시 CSS/JS가 인라인됩니다
audio/scripts/*.txt오디오 원고 15편. 이 텍스트가 내레이션의 원본입니다

챕터 하나 추가하기

  1. src/data.js의 CHAPTERS 배열에 객체를 추가합니다 (id, part, short, title, lede, blocks, analogy, checks, artifacts, quiz, cards).
  2. 내레이션을 추가하려면 TAKEAWAYS에 한 줄 정리를, AUDIO_SECONDS에 길이를 넣습니다.
  3. python3 build.py — 좌측 목록·진행률·발표자 덱이 자동으로 반영됩니다.
빌드 산출물

index.html과 harness-studio.html은 빌드 결과이므로 직접 고치지 마세요. 다음 빌드에서 덮어써집니다. 소스는 항상 src/입니다.

14문제 해결 · FAQ

오디오가 재생되지 않습니다

  • file://로 열었을 가능성이 높습니다. python3 -m http.server로 열거나 배포 주소를 쓰세요.
  • audio/ 폴더가 index.html과 같은 위치에 있는지 확인하세요.
  • 설치 직후라면 캐시가 아직 비어 있을 수 있습니다. 온라인 상태에서 한 번 재생해 주세요.

앱 설치 버튼이 보이지 않습니다

  • iOS Safari는 설치 배너를 지원하지 않습니다. 공유 → 홈 화면에 추가를 사용하세요.
  • 이미 설치했거나 localhost가 아닌 http 주소라면 설치가 비활성화됩니다. HTTPS인지 확인하세요.

기록이 사라졌습니다

  • 브라우저 데이터 삭제, 시크릿 모드 종료, 기기 변경 시 사라집니다. 서버 저장이 없기 때문입니다.
  • 정기적으로 Reference → JSON 내보내기로 백업하세요.

발표자 모드에서 글자가 작습니다

전체화면(F)으로 진입하면 뷰포트가 커져 활자가 함께 커집니다. 프로젝터 해상도가 낮다면 브라우저 확대를 80% 정도로 낮춰 슬라이드가 잘리지 않게 하세요.

진행률이 올라가지 않습니다

진행률은 완료 표시만 셉니다. 체크리스트와 퀴즈는 별도로 저장되지만 진행률에는 포함되지 않습니다.

이 앱의 한계

서버가 없으므로 팀 단위 진도 취합·순위·대시보드는 지원하지 않습니다. 필요하다면 Supabase 같은 무료 백엔드를 붙여 진도 테이블만 동기화하는 방식이 가장 작은 확장입니다.
